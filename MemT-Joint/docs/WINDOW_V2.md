# 短窗口联合训练：memt-window-v2

> 历史协议（当前主流程禁用）：本文只保留旧的窗口前缀实验记录。`memt-common-v1` 当前要求每个 run 从空状态端到端构建，`experiments.joint_config.validate` 会拒绝窗口配置和 baseline reuse；不要用本文命令恢复旧快照。


本版执行用户确认的 M4：B/U/R 与 Answer 使用当前共享参数。Answer 只推理，不增加 Answer loss；旧 `memt-common-v1` 的独立冻结 HF Answer 保留为历史协议。两种协议的分数不能直接当作训练增益。

每步使用同一版本 θk：

```text
冻结基座的窗口前快照 + 截至 T 的8块对话
  → 当前策略采样2条 B/U 轨迹
  → 窗口末 QA 的 Global 反馈
  → 1个锚点：B各2候选、U各2候选、before-U基线
  → 批量贪心续跑至 T，得到 Local 反馈
  → 4道窗口末 QA；每道固定一个库，R做3树/深度4的MoT
  → 同一 θk 的 Answer 批量回答 → 外部固定QA/证据/成本评分
  → B/U Global+Local、R MoT损失 → 一次 Adam 更新为 θk+1
```

同一步的生成会话只同步一次权重、保持 vLLM 驻留。下一步会话入口同步新权重；这部分同步时间计入下一普通步。old/ref/反向开始前结束会话并卸载生成资源。KL reference 始终固定。Answer 缓存绑定 policy_version、问题、时间和完整展示证据，答案/证据标注不进入策略输入。

Global 是**窗口终局回报**。前缀快照来自冻结基座，只含窗口前的训练对话；其历史动作和 Local 贪心续跑动作均不进入损失。窗口改变初始状态分布和信用覆盖范围，不等于原有整段 Global。

响应 token 仍按有效长度归一；B 的 Global/Local 各1/6，U 各1/6，R MoT 1/3。缺失角色/分支、QA不足或没有可供 Local U 的候选时停止，不能复制问题或删掉分支凑成一次更新。

v2 的 B/U 候选回报按调用平均：有效调用取该候选的任务/成本回报，无效调用取 −3，然后在候选之间标准化。旧的“任一调用无效则整个候选 −3”会让多次 U 调用的候选同时饱和，无法区分较少失败的轨迹。严格解析和事务回滚保持不变；历史非窗口协议仍沿用旧奖励。候选内部各调用共享轨迹优势，这不等于逐动作反事实归因；失败比例相同且任务回报相同仍会自然得到零优势。

## 数据准备与审校

`scripts/prepare_windows.py` 只读取 train。首轮选择 session 3/9/19 末尾的三个窗口，冻结基座构建各窗口之前的快照。QA生成只见对应前缀；独立盲答请求不含候选答案/证据，之后另作支持性审查。生成/审查可使用同一冻结基座的独立无状态调用，不能称为独立模型共识。原始请求、响应、拒绝原因和哈希均保留。

执行者还需逐题核对来源、日期和歧义，写 `ASSISTANT_AUDIT.json` 的通过列表，绑定 bundle 哈希；未审校的 bundle 不可训练。训练启动检查 QA、盲答、审查、前缀、模型、快照哈希及实际 cutoff。QA一经冻结，不能根据在线 Answer 输出调整 gold。

每组4题分为2题证据涉及当前窗口、2题只依赖更早前缀；各组不复制题目。题库不足则拒绝开始，以免提速变成只回答最近事实。生成器应使用具体事实的短答案题，泛泛的评论复述、读截止时间即可回答的题不进入白名单。
